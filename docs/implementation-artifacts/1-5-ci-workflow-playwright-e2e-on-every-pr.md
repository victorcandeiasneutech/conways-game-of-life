# Story 1.5: CI Workflow — Playwright E2E on Every PR

Status: review

## Story

As the candidate,
I want Playwright wired into CI with browser binaries installed and failure artifacts uploaded,
so that E2E regressions cannot merge and failures are diagnosable without a local repro.

## Acceptance Criteria

1. **Given** `.github/workflows/ci.yml` has an `e2e` job,
   **When** a PR is opened or updated and affects `apps/web` or `apps/web-e2e`,
   **Then** the job runs `pnpm exec playwright install --with-deps` followed by `pnpm nx affected -t e2e --base=origin/main` and reports a named check status.
   **And** Playwright HTML report artifacts are uploaded on failure for diagnosis.

2. **Given** the Playwright spec passes locally,
   **When** CI runs the same spec,
   **Then** the `e2e` check passes within five minutes for the MVP spec.

## Dev Notes

### What changes in this story

Stories 1.3 and 1.4 added `lint`, `typecheck`, and `test` jobs. This story adds the `e2e` job — the fourth and final required check per architecture §4.10. After this PR merges, all four named checks are in place for branch protection (story 1.6).

### Target `e2e` job to add to `ci.yml`

Add this job block after the `test` job:

```yaml
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: pnpm/action-setup@v4
        with:
          version: 9.8.0
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm exec playwright install --with-deps
      - run: pnpm nx affected -t e2e --base=origin/main
      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report
          path: apps/web-e2e/playwright-report/
          retention-days: 7
```

### Why `nx affected -t e2e` instead of `nx e2e web-e2e`

Architecture §7.2 states the e2e job "Only runs on PRs that affect `web` or `web-e2e`." Using `pnpm nx affected -t e2e --base=origin/main` achieves this: Nx computes the affected set and only runs `web-e2e`'s `e2e` target when `apps/web` or `apps/web-e2e` source files changed. On PRs that only touch CI config, docs, or `libs/*`, the e2e step completes in seconds with no Playwright browsers launched.

### Scaffold `example.spec.ts` — keep for now

`apps/web-e2e/src/example.spec.ts` was generated by `@nx/playwright`. It tests that the page `h1` contains "Welcome" — which currently passes because the scaffold app page renders "Welcome @conways-game-of-life/web". This spec is scaffold noise, not a behavioral assertion of the actual app.

**Action for this story:** Leave it in place. It passes now.
**Action for story 3.1:** Delete it when the app UI is replaced by the actual Conway's Game of Life interface (the "Welcome" h1 will be gone, and CI will catch the break).
**Action for story 4.1:** Add `apps/web-e2e/src/e2e/happy-path.spec.ts` per the architecture spec.

### Playwright config (already correct from scaffold)

`apps/web-e2e/playwright.config.ts` is already configured with:
- `webServer` auto-starts `@conways-game-of-life/web:dev` on port 3000 before tests
- `trace: 'on-first-retry'` captures traces on retry (supports failure diagnosis)
- `testDir: './src'` — Nx preset default

No changes needed to `playwright.config.ts` in this story.

### Artifact upload path

Playwright writes its HTML report to `playwright-report/` relative to the config file location. With the Nx preset, that is `apps/web-e2e/playwright-report/`. The `upload-artifact` step uses `if: failure()` so it only runs when Playwright exits non-zero — not on every passing run.
