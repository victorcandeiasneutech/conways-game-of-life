## 🔍 Challenges and Learnings

### 1 — `moduleResolution: nodenext` + Jest requires careful tsconfig layering

Story 2.1 required resolving three interacting issues:

1. `tsconfig.lib.json` with `src/**/*.ts` glob picked up `*.spec.ts` files → TS2835 (missing `.js` extension) + TS2593 (missing jest types). **Fix:** Add `"exclude": ["src/**/*.spec.ts", "src/**/*.test.ts"]`.
2. `tsconfig.spec.json` referenced `tsconfig.json` which references `tsconfig.spec.json` → TS6202 circular reference. **Fix:** Reference `tsconfig.lib.json` directly.
3. First cross-lib import (`@conways-game-of-life/types`) required `pnpm nx sync` to add the TypeScript project reference.

The three-file pattern is now established and documented. It must be front-loaded in Dev Notes for any new lib that adds Jest.

**Lesson learned:** When creating a lib with `moduleResolution: nodenext` + Jest, document the tsconfig three-file pattern (`tsconfig.json` → `tsconfig.lib.json` + `tsconfig.spec.json`, spec references lib not json) in Dev Notes *before* implementation — not after the diagnostic cycle.

---

### 2 — Sprint-status sequencing artifact

Story 2.4's sprint-status entry was set to `ready-for-dev` in the implementing PR (the status at branch creation time) rather than `review`/`done` at merge. The `ready-for-dev` state persisted on `main` after the PR landed.

**Lesson learned:** The dev agent should update `sprint-status.yaml` to `review` (or `done`) in the same commit that completes implementation — not leave it at whatever status was set when the branch was created.

---

### 3 — Planning docs can contain errors in computed ACs

The all-alive 3×3 corner survival case (story 2.3) demonstrates that epics.md ACs for deterministic systems should be treated as a starting point, not ground truth. Hand-computing the expected output before writing the test caught a real error.

**Lesson learned:** For any AC that asserts the output of a deterministic function, hand-compute the expected value independently. Do not copy from planning docs without verification.
