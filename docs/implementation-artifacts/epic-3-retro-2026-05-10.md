## 🎉 What Went Well

### 1 — Upfront pain, downstream ease

Story 3.1 absorbed the full cost of the triple-tool resolution problem (tsc + Turbopack + IDE). Once the fix was documented — `baseUrl: "."` in `apps/web/tsconfig.json` and `moduleResolution: bundler` in `libs/sim` — it stayed fixed. Stories 3.2–3.5 had zero import resolution issues.

**Pattern:** Four failed attempts in 3.1 → zero in 3.2–3.5. Document and solve once, compound across the remaining stories.

### 2 — Hook designed for extension from the start

`useSimulationLoop` in story 3.3 was built to read `genPerSec` through a `useRef` from day one, even when `genPerSec` was still a module constant. Story 3.5 — the speed slider — required exactly one change: `useState(10)` replacing the const. The hook needed zero modification. This was intentional design, not luck.

`clearGrid` and `randomizeGrid` were already exported, tested, and boundary-enforced from Epic 2. Story 3.4 (Clear + Randomize) was two reducer cases and two buttons. No lib changes. The upstream purity made downstream wiring trivial.

`data-testid="gen-count"` was placed in story 3.1, before any Playwright story existed. `aria-label="Speed (gen/sec)"` was added with the slider in story 3.5. Both create clean targets for Epic 4's testing and accessibility work with no rework needed.

## 🔍 Challenges and Learnings

### 1 — The triple-tool resolution mismatch (story 3.1)

The root cause was three interacting issues:

1. **`moduleResolution: nodenext`** in `libs/sim/tsconfig.lib.json` required `.js` extensions on relative imports. Turbopack cannot resolve `.js` → `.ts` for source files.
2. **`baseUrl` mismatch:** `apps/web/tsconfig.json` inherited `baseUrl: "."` from the workspace root, so `paths` entries with `../../libs/sim/src/index.ts` resolved from the workspace root — two levels above the intended base.
3. **Four failed intermediate fixes** were attempted before arriving at the correct combination.

**Correct fix:**
- Remove `moduleResolution: nodenext` from `libs/sim/tsconfig.lib.json` (inherit `bundler` from base)
- Remove `.js` extensions from `libs/sim/src/index.ts` exports
- Add `"baseUrl": "."` to `apps/web/tsconfig.json` so tsc anchors to `apps/web/`, matching Turbopack

**Lesson learned:** When Next.js (Turbopack) + tsc + IDE all disagree on module resolution, the fix lives in the *library's* tsconfig (moduleResolution) AND the *app's* tsconfig (baseUrl). Check both before iterating on `next.config.js` settings — Turbopack largely ignores webpack-layer aliases.

---

### 2 — Sprint-status `done` vs `review` sequencing

Story 3.2's sprint-status was updated to `done` before the PR merged. Victor caught this immediately. The correct rule:
- `review` when implementation commits land on the feature branch
- `done` only after the PR merges on `main` (next sprint-status update)

Stories 3.3–3.5 followed this correctly.

**Lesson learned:** The dev agent's last commit on a feature branch must set sprint-status to `review`. The `done` transition happens on `main` at the start of the next story's setup.

---

### 3 — Pre-existing lint warning carried forward

`apps/web/next.config.js` has had an unused eslint-disable directive warning since Epic 1. It has been carried through every lint run in Epics 2 and 3 without being addressed. Zero functional impact, but it's noise.

**Lesson learned:** Carry-forward warnings should have an explicit "will fix in story X" note in the story that introduces them, or be fixed immediately. Letting them accumulate makes the lint signal noisy.
