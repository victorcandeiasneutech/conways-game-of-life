## 🔍 Challenges and Learnings

### 1 — Lint rule conflict in Playwright spec (story 4.1)

Initial spec used `canvas.boundingBox()` with `if (!box) throw`. This triggered `playwright/no-conditional-in-test`. Replacement with `expect(box).not.toBeNull()` + `box!` triggered `@typescript-eslint/no-non-null-assertion`. Two rules in conflict.

**Correct resolution:** Question whether the bounding box was needed at all. At desktop viewport, the canvas is 120×120px with no CSS scaling. The hardcoded `CELL = 12` constant was always the right answer — the lint conflict was a signal that the design was wrong, not that the syntax needed adjusting.

**Lesson learned:** When lint rules conflict in a spec, interrogate the design before trying to satisfy each rule in isolation. The conflict is usually pointing at an unnecessary complexity.

---

### 2 — Playwright browser context vs. page-level settings (story 4.3)

`page.setViewportSize({ width: 375, height: 667 })` looked complete. CI caught the WebKit failure: "The page does not support tap. Use hasTouch context option to enable touch support."

`setViewportSize()` changes pixel dimensions only. `hasTouch: true` is a browser context option — it must be set at context creation via `test.use()`, not after the page is open.

**Correct fix:** `test.use({ viewport: { width: 375, height: 667 }, hasTouch: true })` at the file level.

**Lesson learned:** Playwright context capabilities (hasTouch, permissions, locale) are distinct from page-level settings. When a spec needs touch, set `hasTouch: true` via `test.use()` — `setViewportSize()` alone is not sufficient.
