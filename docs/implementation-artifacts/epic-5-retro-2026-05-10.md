## 🎉 What Went Well

### 1 — Zero CI failures across the entire epic

First epic with a clean branch record on every PR. No lint conflicts, no typecheck surprises, no WebKit gotchas. The two CI failure patterns from Epic 4 (Playwright lint conflict, `test.use()` for hasTouch) were never encountered because Epic 5 introduced no new E2E specs.

**Pattern:** Additive epics with no new Playwright specs inherit zero E2E risk. The failure surface shrinks naturally.

### 2 — Auto-resize resolved the open architecture question cleanly

The architecture doc flagged "pattern-larger-than-grid" as an open question with "auto-resize recommended." `buildPlacedGrid` implements it: `max(current.width, pattern.width) × max(current.height, pattern.height)`. No dialog, no error, no silent crop. Gosper Gun (36×9) on a 30×30 grid auto-resizes to 36×30 on Place.

**Pattern:** When the architecture doc flags a decision as "recommended," implement it as documented. Don't re-litigate at story time.

### 3 — `NamedPattern` in `libs/types` preserved the type hierarchy

The interface landed in `libs/types` (no deps), not `libs/sim`. `libs/sim` imports it as it does `Grid`. The module boundary enforced the right location without any friction.

**Pattern:** The type hierarchy (`scope:types` → no deps, `scope:sim` → depends on `scope:types`) continued to guide decisions correctly.

### 4 — Behavioral specs, not coordinate snapshots

Story 5.1 tests verify canonical Conway dynamics: canonical glider translates (1,1) after 4 steps; blinker oscillates with period 2. These constrain behavior, not implementation detail. They would catch a wrong-direction glider or a blinker that doesn't oscillate.

### 5 — Reducer stayed a pure state updater

`buildPlacedGrid` computation (auto-resize + centering) lives in the event handler. The `place` action carries a pre-computed `Grid`. The reducer has no imports from `libs/sim`, no logic beyond a state swap.

**Pattern:** Keep reducers as pure state updaters. Push computation to the call site.

### 6 — Epic 4 retro pipeline applied correctly

Action item 3 from Epic 4: "Note boundary handling requirement for `placePattern` in story 5.1 Dev Notes." Story 5.1 dev notes explicitly documented it: silently skip out-of-bounds cells, same defensive posture as `randomizeGrid`. Third epic in a row where the retro → story pipeline worked.

## 🔍 Challenges and Learnings

### 1 — `moduleResolution: nodenext` in `libs/types` requires a persistent mental context switch

`libs/types` uses `moduleResolution: nodenext`, which requires `.js` extensions on export paths in `index.ts` (e.g., `'./lib/patterns.js'`), even though the source file is `.ts`. This violates muscle memory and is a recurring context switch every time a new type is exported from `libs/types`.

**Status:** Known, documented, not a problem — but a friction point that will recur in every future story that adds a type.

**Mitigation already in place:** The convention is documented in story dev notes. Any future story adding a type to `libs/types` should check the index.ts pattern first.
